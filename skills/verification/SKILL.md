# 検証（verification）

実装の結果が仕様の通りかと、仕様が正しいかを確かめる。仕様が正しいかは、仕様をもとに実際に試すなどして確かめる。main が自ら行う場合も、検証エージェントに委ねる場合も、このスキルに従う。

## 何を検証するか

- 変更に応じた方法で中身を確かめる。
- 仕様を変える作業は、実装を含まなくても仕様が正しいかを検証する。
- 計画だけを変える作業は、検証する対象がないため省いてよい（確認は省かない）。

## 結果の残し方

| 検証の種類 | 残し方 |
|---|---|
| 誤字・リンク・簡単なスクリプト修正などの単発の確認 | 方法と結果を PR の「変更」に書く |
| 情報取得方法の試行、外部環境での動作確認、仕様の妥当性の検討など、条件や根拠を後で参照する価値がある結果 | `verification/` に置き、同じ PR に含める（置き場所は `layout` スキル） |

- 試していないことを試したように書かず、試せなかった範囲と理由を示す。

## 再検証

- 前回検証したコミットからの変更と、それを要約・参照する箇所を対象とする。
- 結果に、検証したコミットと、対象・対象外の範囲を書く。
- 前回のコミットが分からなければ範囲を絞らない。

## main へ返す結果（委任された場合）

- 検証したコミット
- 検証の方法と結果
- 対象・対象外の範囲と、試せなかった理由
- 見つかった問題
- 時間の記録

サブエージェントとして動くときは、再委任、全体の Issue・PR・ログの管理、マージを行わない。問題を見つけても、指示がなければ自分で直さず main へ返す。
