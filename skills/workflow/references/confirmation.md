# 確認（手順 7）

確認は、依頼を満たし、変更と検証結果を正しく説明しているかを確かめる。検証を省く作業でも確認は行う。main が自ら行う場合も、確認エージェントに委ねる場合も、これに従う。

## 毎回確かめること

- 依頼を満たしているか。未達の要件と理由を明示しているか。
- PR の説明が実際の変更・検証結果と合い、作業の文脈を持たない人にも分かるか。
- 人の判断や追加作業が必要なことを伝えているか。すでに決まったことを聞き直していないか。

## 変更に関係するときに確かめること

- リンク、配置（`layout.md`）、計画の状態、Issue との整合、ログの形式（`work-log.md`）など。
- `verification/` の記録が、試した条件・根拠と結論を正しく示しているか。
- 分量を増やすだけの重複や不要な書式指定がないか。

## まとめ方

- 問題と、確認したコミットをまとめる。
- 確かめた範囲と未確認の範囲を明示する。
- 人の手助けが必要な部分をレビュー項目にする（書き方は `issue-pr.md`）。AI が自分で確かめられることは、確かめてから示す。
- 確認済みの項目を PR に列挙する必要はない。

## 再確認

- 前回からの差分、PR 本文・Issue の更新と、指摘した問題の修正に絞る。
- 前回のコミット・指摘・本文の更新箇所が分からなければ範囲を絞らない。

## main へ返す結果（委任された場合）

- 確認したコミット
- 見つかった問題（根拠つき）
- 確かめた範囲と未確認の範囲
- レビュー項目にすべきこと
- 時間の記録

サブエージェントとして動くときは、再委任、全体の Issue・PR・ログの管理、マージを行わない。問題は main が直すため、指示がなければ自分で直さない。
