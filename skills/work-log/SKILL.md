# 作業のログ

メインエージェントは、作業ごとにログを 1 ファイル書き、同じ PR に含める。

- ファイル名：Issue があれば `work/実施/log/Issue番号.md`、なければ `work/実施/log/pr-PR番号.md`
- 作業中に事実と時刻を控え、PR 作成後の手順 6 でまとめ、やり直したときは追記する。
- 新規ログのひな形は `work/実施/templates/log.md` を使う。

## 記録すること

作業のタイトル、Issue があればその番号、PR 番号と、次を記録する。

### 起きたこと

- 確認の指摘、レビューによる修正、担当者の訂正・不便・よかった点、迷った箇所、目的に照らした気づきを、根拠とともに書く。
- 該当する事実がなければ「なし」と書く。
- 担当者の発言は要旨を根拠にできる。
- 単なる案の選択は訂正に含めない。
- チャットで伝えられた困り事やよかった点も、「記録して」と頼まれなくても状況とともにセッション終了前に残し、記録した要旨を短く伝える。

### 時間の記録

- 各役割が作業中に計測し、メインエージェントが集約する。
- 項目と計測方法は、作業対象リポジトリの「時間の記録」に従う。

## 残し方

- 観測した事実とその場の対応を残す。原因の仮説や変更案、採否は作業対象リポジトリの「業務の改善方法」に従って扱う。
- 会話の全文、認証情報、個人情報は残さない。
- ログは検証・レビューの対象外とし、形式の確認は `confirmation` スキルに従う。
- ログを置いたことは PR の「変更」に書かない。

## ツール

- Issue がある作業では、計測と時間表の生成に `work/実施/tools/work_log.py` を使える。作業対象リポジトリの「利用手順」に従い各役割が計測し、**メインエージェントだけがログを生成する。**
- 管理マーカーの外の文章と手書きの時間記録は保持する。
- Issue のない作業にはツールが対応していないため、手書きで記録する。
