## 起きたこと

- 検証で 2 つの不具合を見つけて直した。1 つは、`time` で書き換えると空の欄が空白 2 つになり、ひな形の形と変わること。もう 1 つは、PR・Issue を確かめた後の終了時に、一時ファイルを消す `trap` が関数のローカル変数を参照してエラーになること。
- PR 本文の最初の案に、試しに使った非公開リポジトリの名前と PR・Issue の番号を書いたところ、Claude Code の自動判定で PR の作成が止められた。workloop は公開リポジトリなので、名前と番号を伏せて書き直した。
- この作業のログをスクリプトで確かめたところ、本文にコードとして書いた `<!-- -->` まで、コメントの消し忘れと判定された。バッククォートで囲んだ部分を除くように直し、検証をやり直した。
- ひな形の `<!-- -->` の扱いが決まっていなかった。既存のログでは消されていたので、SKILL.md 5 章に、書いたら消すと決めた。

## workloop への気づき

- 公開リポジトリの PR やログに、ほかの（非公開の）リポジトリの名前や中身を書かないという決まりがない。7 章の「残し方」は会話の全文・認証情報・個人情報だけを挙げていて、今回のように別のリポジトリの情報を扱う作業は想定していない。
- この作業は #5 に依存しているが、Issue がない作業どうしの依存（blocked by）を表す方法がない。今回は、PR の向き先を #5 のブランチにし、マージの順番をレビュー項目に書いた。
